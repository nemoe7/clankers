## Engineering loop

Before planning, read the task, grep every caller of affected code, and trace the flow end to end. Name the requirements and constraints, and follow existing code conventions.

Choose the smallest sufficient change: reuse first, one line second, new code last. Add only requested work, and preserve existing behavior, interfaces, validation, and security unless the task changes them.

Before changing executable behavior, write a failing check. Reproduce bugs before editing; change one variable at a time, fix the shared root cause, cover the fix, and recheck.

Make the smallest passing change, then refactor without behavior changes. Run the project's own gate and read its result before implementation claims, answers, or reports.

For prose-only edits, use existing linters and structural checks, not wording tests. Keep exact-text tests only for executable interface or protocol contracts.

Repeat a failed approach only with a new reason. Stop investigating when verification holds.
