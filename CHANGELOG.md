- **Deferred** — the `since=<lastmessage>` form is documented by ntfy and read from its server source, not measured end to end: the read path is GET-only, so a second message cannot be published to a fresh topic to produce a two-read sequence. A live anchored read lands the next session whose channel carries a note.
- Upstream is the reason, not an invention: ntfy's API docs state that a poll without `since=` re-reads the topic's whole cache, that a replay is capped at the newest messages fitting 10 MB per topic with `X-Messages-Truncated: 1` on a capped response, that replayed bytes count against the daily bandwidth budget, and that a repeated poller should pass `since=<last message ID>` instead.
- The stale anchor was read in the server, not guessed: the since-ID query is `id > COALESCE((SELECT id FROM messages WHERE mid = ?), 0) AND published = 1` (`message/cache_sqlite.go` on `main`, read over `api.github.com`), so an anchor that has aged out of the 12-hour cache resolves to the start of it and the whole cache comes back, which the message-id dedup absorbs. Losing the log therefore costs one full read and never a note, which is why no `since=` state file was added.
- `scripts/ntfy_steering.py`: `load_seen` becomes `log_ids`, returning the ids the log recorded in delivery order, one read serving both dedup and the anchor; the new `pull_url` walks it backwards to the newest id and prints `Next pull: <url>` on the empty-body path and the delivery path alike, including after a `current` baseline hold, so the next read starts above the held messages. A message that carried no ntfy id is stamped `digest-...`, which the server cannot resolve, so it is never offered as an anchor and such a body leaves the anchor where it was.
- `skills/arena-live-steering/BASELINE.md` carries the unsquashed wording first, on the house order: the step-3 URL, the log's dual role, the unconditional cadence, the script bullet, the Limits entry, the example's `Next pull:` line, and the ack bullet. `SKILL.md` is the squashed mirror and `REFERENCE.md` gains the anchor mechanics, the docs citation, the source clause, a moved-log note in Troubleshooting, a `since=all` escape hatch for a note believed missing, and the note that an anchored empty read is the common quiet case rather than a fault.
