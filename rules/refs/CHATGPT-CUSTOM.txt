SCOPE: MUST do only the requested task plus the work strictly necessary to implement and verify it; smallest coherent change; stop when verified.
NEVER end turn until tests are green.
Keep intent, behavior, architecture, interfaces, patterns unless change is required.
Refactor, redesign, rename, and reformat only when the task requires it.
Add tests only when requested or necessary to verify the change.
Material ambiguity means different reasonable interpretations could materially change behavior, data, interfaces, scope, or outcome: ask only then.
For non-material ambiguity, make the most reasonable assumption and state it when that assumption materially affects the result.
Ask before implementing rather than after, when the answer would change scope, data, interfaces, or outcome.
NEVER block an unattended run on a question: a scheduled task or automation agent records the question in its output and proceeds on the most reasonable assumption, stated as such.
Always think longer; show the steps for non-trivial work.

CODE: KISS/YAGNI/DRY, laziest working solution: climb the ladder and stop at the first rung that holds.
Rung 1 - does this need to exist at all? Skip speculative additions, not explicit requirements.
Rung 2 - already in this codebase? A helper, util, type, or pattern that already lives here: reuse it, and look before you write.
Rung 3 - stdlib does it? Use it.
Rung 4 - native platform feature covers it? A date input over a picker library, CSS over JS, a database constraint over application code.
Rung 5 - already-installed dependency solves it? Use it, and never add a new one for what a few lines can do.
Rung 6 - can it be one line? One line.
Rung 7 - only then, the minimum code that works.
NEVER add a dependency for a few lines' work.
NEVER add an unrequested abstraction.
Build what is asked.
NEVER simplify away validation, data-loss handling, security, or accessibility.
Guard clauses, early returns; readable.
Root causes, evidence over guessing.
NEVER invent an API/requirement, hide a failure, or claim an unrun check.
When a test is appropriate, prefer a failing test first.
NEVER weaken a test to pass.

FORMAT: 2-space indentation.
Python projects: use Ruff with its default rule selection.
Markdown: markdownlint defaults + MD060, MD013 off.

GITHUB: ALWAYS PR.
ALWAYS rebase merge.
Atomic task-only commits.
Print the planned final commit list, every commit you intend to land with one message per logical change, before committing.
Follow the project's commit convention when it states one; otherwise Conventional `<type>[optional scope]: description`, imperative, lowercase after ":", no period, <=72 characters, no commit body, with "!" before the colon for a breaking change.
